## Подключение

См. схему `korona-esp32h2-schema.svg` из чата. Коротко:

| Что | Куда |
|---|---|
| Зелёный провод ленты (DATA) | GPIO4, через резистор 330 Ом (+ шифтер уровня, если понадобится) |
| Красный провод ленты (+12V) | напрямую на 12V шину (не через ESP32!) |
| Белый провод ленты (GND) | общий GND с платой и БП |
| Питание платы ESP32 | 5V от DC-DC step-down (12V→5V) и GND |

**GPIO4 занят как раз под это** — свободен, ни с чем не конфликтует (не strapping, не USB, не UART).

---

## Первая прошивка

Долгая — тянется Zigbee-стек, минут пять-десять.

Если плата не определяется при заливке (как и с магнитолой): GPIO8 подтянут к 3V3 через 10 кОм → зажать **BOOT** → нажать и отпустить **RESET** → отпустить **BOOT** → закрыть монитор порта → Upload.

---

## Первым делом после прошивки

В мониторе порта (115200):

1. Нажми `?` — увидишь список пресетов и клавиш
2. Нажми `T` — прогон всех цветов по очереди, пауза 1.5 сек между. Смотри на ленту:
   - если цвета явно перепутаны местами (красный светится зелёным и т.п.) — поменяй в коде `NEO_GRB` на `NEO_RGB` или `NEO_BRG` (строка с `Adafruit_NeoPixel strip(...)`), перешей
   - если светится не вся лента — увеличь `NUM_LEDS`
   - если в конце ленты остаётся тёмный необъяснимый кусок при и так большом `NUM_LEDS` — вероятно обрыв/плохой контакт на пайке, а не настройка кода
3. Нажми `0` — переключить главный выключатель
4. Нажми `S` — общий статус

## Добавление в Home Assistant

### ZHA

Настройки → Устройства и службы → ZHA → «Добавить устройство» → подать питание на плату. Появится одно устройство с 13 переключателями:

- **endpoint 10** — главный вкл/выкл
- **endpoints 11–20** — 10 кнопок-пресетов (сами гаснут через секунду)
- **endpoints 21–22** — «ярче» / «тише»

### Zigbee2MQTT

Без конвертера Z2M опознает устройство как неизвестное, но всё будет работать — кластеры стандартные On/Off, только имена придут технические (`l1`, `l2`…).

Файл `z2m_external_converter/korona.js` даёт человеческие имена и группирует в один "exposes"-список. Положи его в папку `external_converters` внутри конфига Z2M (создай, если её нет) и добавь в `configuration.yaml` Z2M:

```yaml
external_converters:
  - korona.js
```

Перезапусти Z2M и заново удали/добавь устройство в сеть (или сделай `Reconfigure` из UI).

**Важно:** сопоставление модели в конвертере я сделал по строке `"Korona ARGB"`, которую прошивка отдаёт как имя модели для endpoint 10 — это должно сработать, но конкретно эту связку endpoint↔Basic-cluster для Arduino Zigbee library вживую не проверял. Если после добавления Z2M всё равно покажет "неизвестное устройство" — скинь мне лог сопряжения (Z2M → Devices → добавляемое устройство → там будет `manufacturerName`/`modelID`), поправлю за минуту.

## Логика

- Нажатие пресета — сразу включает ленту в этот цвет с текущей яркостью, главный выключатель в HA показывает «вкл»
- Главный выключатель выключает ленту (гасит), но **помнит** последний пресет и яркость — следующее включение тем же тумблером вернёт тот же цвет
- «Ярче» / «Тише» тоже включают ленту, если она была выключена (как обычный диммер)
- Яркость **не хранится между перезагрузками платы** (сброс питания = яркость по умолчанию 160/255). Если нужно, чтобы помнила — допиши сохранение в `Preferences` (NVS), скажи — сделаю

## Добавление своих пресетов

В `main.cpp` — просто дописать строку в массив `PRESETS[]`:

```cpp
{ "Moi_cvet",  120, 40, 200 },
```

Если пресетов становится больше 10, ещё нужно:
1. Добавить `MAKE_PRESET_CB(10)` (и т.д. по числу новых) рядом с остальными
2. Добавить `onPreset10` в массив `PRESET_CB[]`

Имена — латиницей: Zigbee-стек не гарантирует корректную передачу кириллицы в поле модели устройства.

## Отличия от магнитолы

| | Магнитола | Корона |
|---|---|---|
| Выход | ИК-светодиод (RMT) | ARGB DATA (Adafruit_NeoPixel, тоже через RMT) |
| Обратная связь | датчик реального состояния (АЦП) | нет — состояние чисто программное |
| Кнопки | команды пульта | пресеты цвета + ярче/тише |
| Эндпоинтов | 16 | 13 |
